# snapshot_project

LilyGo T-QT (ESP32-S3) — designer — generated by **Grumpy's Rusty Platform** (Arduino C++).

## Build it

```bash
arduino-cli core install esp32:esp32
arduino-cli compile --profile default
arduino-cli upload --profile default -p /dev/ttyACM0
```

The board is recorded in `sketch.yaml` as `esp32:esp32:esp32s3`, so no `--fqbn` is needed.

## What is here

| file | who owns it |
| --- | --- |
| `snapshot_project.ino` | the sketch entry file Arduino needs; it only includes `main.h` |
| `src/main.cpp` | `setup()` and `loop()`. The place for code that is not about the screen |
| `src/panel.cpp` | the panel, its pins and its init sequence. **The Designer rewrites this** |
| `src/ui.cpp` | the screen. **The Designer rewrites this** |
| `src/ui_handlers.cpp` | your code. The Designer appends a stub per widget event |

## The panel

**0.85" GC9107 128x128**, 128x128 native.

| signal | pin |
| --- | --- |
| SCK | GPIO3 |
| MOSI | GPIO2 |
| CS | GPIO5 |
| DC | GPIO6 |
| RST | GPIO1 |
| BL | GPIO10 (active low) |

## Notes

- **No libraries are needed.** This project draws with the panel driver in `src/panel.cpp`, so it builds on a freshly installed core. The LVGL object tree arrives with the designer emitter.
- The LED, the pins and the panel facts come from the extension's own board catalogue, so what is written here is what was verified on that board rather than a datasheet guess.
- On this board the panel is soldered on, so the pins are the board's and not a module choice.
