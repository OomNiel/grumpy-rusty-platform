# Grumpy's Rusty Platform

This project is still under active development, with many features still to be tested — use it at your own risk.

The source is public at [github.com/OomNiel/grumpy-rusty-platform](https://github.com/OomNiel/grumpy-rusty-platform), and every release carries the packaged `.vsix`.

Embedded development for **Raspberry Pi Pico** and **ESP32** boards in **Rust** using [Embassy](https://embassy.dev) and [probe-rs](https://probe.rs), or in **C++** using the Arduino cores and **LVGL 9** — one extension, one Designer, either language.

## Features

- **Two languages, one Designer**: a project is generated as a Rust crate (Embassy, `probe-rs`, `espflash`) or as an **Arduino sketch** (`arduino-cli`, the `rp2040` and `esp32` cores, LVGL 9 for the display). The wizard asks once, and everything after it — the toolbox, the canvas, the handler stubs, Build/Flash/Monitor — follows the language the project was created in. A C++ project gets the same WYSIWYG designer as a Rust one: the same `designer/panel.ui.json`, the same views and events, and a generated `src/ui.cpp`/`src/ui.h` that the Designer rewrites, so your own code belongs in `src/ui_handlers.cpp` and survives every save. Pictures are decoded when the design is saved, so an image or a composite icon is drawn from pixels in the flash rather than from a file the sketch would have to parse.

- **Project Wizard**: Support for RP2040, RP2350 (Pico, Pico 2, Pico W, Pico 2 W) and ESP32 family chips. A board that can take more than one display module asks which one is wired — the T-QT's two panel revisions, the DevKitC's ST7789, ILI9341-with-touch or 4" ST7796-with-touch module — and records the answer in the project's `Cargo.toml`. The panel record carries what only the glass can say: the T-QT's newer GC9A01 revision draws inverted, takes its colour in BGR order and is bonded into the controller's RAM off the origin — two pixels across and one down, without which its last row and column were never written — and the generated builder does all three for it alone. The ESP32-035 panel is design-first: picking it goes straight to the WYSIWYG designer, with no template menu. The ESP32-DevKitC V4 offers only the WYSIWYG designer and the Bluetooth LE peripheral.
- **Embedded Rust & Embassy**: Generates clean structures with `setup()` and `main()` loops, separating board configs and headers.
- **Toolchain Manager**: One-click installer for `rustup`, targets, prebuilt `probe-rs` (with SHA-256 checks), `espup`, and `espflash`.
- **Debugging & Monitoring**: Full SWD debugging with `probe-rs` and RTT for RP boards, plus serial flashing/monitoring via `espflash` for ESP chips.
- **WYSIWYG Designer**: Design panels visually on the Sunton CYD, the LilyGo T-QT, an ESP32-DevKitC with a display module, and **all four Raspberry Pi Pico boards with a TFT module wired to them** — a Pico has no soldered panel, so there the panel is a *project* fact: pick the module (1.54" ST7789, 2.8" ILI9341 with touch, 4" ST7796 with touch) and fill in the GPIO numbers, with an SD socket on its own pins and a software clock (set from the flash time, or from Wi-Fi SNTP on the W boards). The pins go into a generated `src/panel.rs` that the Designer rewrites, so `src/main.rs` is written once and never rewritten. It writes `designer/panel.ui.json` and generates markup for `include_gui!`. The canvas follows the panel the project was generated for (size and touch controller included), and the control bar carries a switch for the project's *cargo features* — SD (the card's FAT filesystem) — a **Brightness** slider for the backlight, and a **zoom** menu that reaches 250 % and 300 % for close work. The touch keypad has cursor keys — `<-` / `->` move the caret and the next key overwrites the character under it — a **SHIFT** key that capitalises the next character and then goes back to lower case by itself, and a **CAPS** key that locks capitals on until it is pressed again; every key's caption follows the state. Pictures are drawn on the canvas from the project's own files — BMP, PNG, JPEG, GIF and WebP, read by the extension and decoded by the panel's browser, so the canvas shows what the board will get — and a widget whose pixels are not there yet draws a dashed frame carrying the file's name. An image can also carry a **border** (colour and width) and **rounded corners**; the board cuts the picture to the corners instead of painting over them, and a progress bar's fill follows its track's corners the same way. An `sd:/NAME.BMP` picture is still the board's to fetch, and is flagged on save while the card is off.
- **Multiple views per design**: A tab strip above the canvas holds one tab per view — add with `+`, and right-click a tab to rename it, duplicate it, delete it, or make it the view the board **starts** on (the tab carries a dot; the strip keeps your order). **All views** draws the other views as dashed outlines, so a widget dropped on the wrong view can be found without switching tabs. A view is a *layer* of the one screen: every widget is compiled into the same markup, and the generated `ui.rs` hides the views that are not on show, so switching costs a few flag writes rather than a rebuild. `navigate` switches view with no code at all — on a click for a button, on the choice for a dropdown, on Enter for a keypad — and `design.show_view(View::X)` drives it from the app when a timer or a sensor should decide. Only the view on show is driven: a clock on another view is not ticked, so nothing off-screen paints over what is on the glass.
- **Panel backlight**: Dimmable from 0 % to 100 % by PWM on the panel's BL pin, at compile time (`BACKLIGHT_BRIGHTNESS` in `.cargo/esp-config.toml`), so the Designer's slider never edits `src/main.rs`. Offered only for a panel that has a BL pin wired, and inverted automatically for an active-low transistor; a project that does not mention it is fully on.
- **Clock & Time Sync**: A design's clock follows the host PC's time, set or served over the serial port (the board asks `TIME?` when its RTC has never been set) and kept in the chip's RTC; a board with no PC on the cable falls back to Wi-Fi SNTP via the generated `src/net.rs`. What the host writes is the dated line `TIME YYYY-MM-DD HH:MM:SS` followed by the bare `TIME HH:MM:SS`, so the calendar day survives a power cycle with no network at all. The Designer starts a listener automatically for an open clock design, closes it for Flash/Monitor, and restarts it when the flash ends; new ESP projects bake in the host's UTC offset. The hour numbers' distance inside the tick ring is a design property (*Number inset*, in character widths, stepped by 0.1).
- **SD card switch**: The Designer shows an **SD** switch in the control bar for the Sunton CYD (the only board with a card). It is a cargo feature, because enabling the card is what pulls the FAT filesystem (`embedded-sdmmc`) into the build; the dedicated `sdcard`/`board` templates always include it. Designs naming `sd:/NAME.BMP` images are flagged on save while the card is off.
- **C++ toolchain, detected or installed**: `arduino-cli` and the cores are found on the machine (or installed from the sidebar), the sketch is compiled into the folder's own `.arduino` build directory, compiler errors land in the Problems pane with their file and line, and **Flash** programs the board through whichever route it has: a UF2 over BOOTSEL or `picoprobe_cmsis_dap`, or the ESP32's serial uploader. **Clean** deletes the build folders and reports how much it freed.
- **Crates.io Library Manager**: Curated catalog and sparse index integration.
- **Local AI Assist**: Optional, fully local, privacy-first AI coding assistance (supports external endpoints or local bundled runtimes like `llama-server`) that helps implement functions, fix build errors, and inspect board hardware constraints. It reads the editor's own evidence: the **selected lines** (numbered, with a marked window either side), the **Problems pane** (errors first, deduplicated, the cut stated) and the **Debug Console** of a `probe-rs` session (`[stopped]` and `[exited]` where they happened) — with a **Console only** switch for "what does this output mean?". **Enter** sends, **Shift+Enter** starts a new line, **Abort** stops an answer in flight, and the conversation follows the newest row while you are at the bottom. The panel has two modes: **Full Assist**, where you ask in your own words, and **Rust Assist**, which watches the active `.rs` file for a `//~ keyword` line — `//~ let`, `//~ loop`, `//~ match`, `//~ option`, `//~ result` and a dozen more — and posts worked examples of that construct as the answer. The same mode watches a `.cpp` or `.ino` file in a C++ project, where the keywords are C++'s and LVGL's (`//~ struct`, `//~ class`, `//~ switch`, `//~ lvgl`, …), and the assistant is told the project's language: it answers in C++ about the sketch's own files, and only code in that language is offered for applying. Conversations are kept per project, and the chat itself reads like a conversation: long lines, URLs and code blocks wrap in the panel instead of scrolling sideways. Code in an answer is applied from a button under it, and **Fix this line** replaces a single diagnosed line — it cannot delete anything else.
- **Packaging Tools**: Package firmware and helper scripts directly into `.deb` installers.

## Installation

Grab `grumpy-rusty-platform-<version>.vsix` from the [latest release](https://github.com/OomNiel/grumpy-rusty-platform/releases/latest), or build it from source (the extension is not yet published to the Marketplace):
```bash
git clone https://github.com/OomNiel/grumpy-rusty-platform.git
cd grumpy-rusty-platform
npm install && npm run compile
npx vsce package
code --install-extension grumpy-rusty-platform-*.vsix
```
